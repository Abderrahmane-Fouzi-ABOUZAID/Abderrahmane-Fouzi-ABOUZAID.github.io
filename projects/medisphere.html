Healthcare systems / Java + Nuxt / Collaborative project

Medisphere healthcare management

A layered healthcare platform for patient, doctor, consultation, medical-record, and administrative workflows, with role-based access, managed sessions, and audit logging.

Team

01 / Challenge

Model sensitive healthcare workflows without collapsing every role into one interface.

The system needed to represent patients, doctors, administrative staff, consultations, clinical notes, prescriptions, medical orders, history, reports, and an audit trail. The architecture had to keep data access separate from request handling and apply permissions consistently across different user roles.

  1. Nuxt viewRole-specific workflow
  2. REST endpointValidated request
  3. AuthorizationSession and role check
  4. DAO layerPrepared data access
  5. AuditUser, action, and time

02 / Collaboration

Co-built with Nasreddine El Gourji.

The project was designed and implemented collaboratively. The repository records both contributors across requirements, diagrams, backend models and services, frontend development, and presentation work.

The final source contains 34 Java files with 4,774 lines and a Nuxt application with 20 routed pages. Those figures were measured from the local source rather than copied from presentation claims.

Accuracy change: the previous portfolio claimed performance and test-coverage percentages that the repository does not verify. Those claims have been removed.

03 / Architecture

Layered data access with explicit domain structure.

Domain

11-table schema

Users, patients, doctors, staff, consultations, clinical records, reports, and audit events form the core model.

Data access

DAO pattern

Data-access objects isolate SQL work from servlet request handling and the frontend contract.

API contract

Typed response wrapper

A generic API response shape gives the frontend consistent success, message, and data handling.

Frontend

Role-specific Nuxt routes

Admin, doctor, and patient views expose the workflows appropriate to each role.

04 / Security

Security controls follow the healthcare data boundary.

Passwords use bcrypt. Authentication uses managed sessions, protected endpoints require role checks, SQL access uses prepared statements, and significant operations are represented in an audit-log model.

The three roles are administrative staff, doctor, and patient. The design separates broad administrative operations, assigned-patient clinical work, and a patient's access to their own information.

Measured scope: 11 database tables, three roles, eight principal backend route groups, and 20 Nuxt pages.
